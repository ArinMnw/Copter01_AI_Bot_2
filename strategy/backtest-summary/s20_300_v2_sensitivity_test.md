# S20.300 v2 — Rule #14 Sensitivity Test (ขยับพารามิเตอร์ทีละตัว)

วันที่ 2026-10-03 | ต่อจาก walk-forward และ rolling walk-forward ที่ผ่านแล้ว — รอบนี้ทดสอบว่า PF ที่ได้มั่นคงแค่ไหน ไม่ใช่ "จุดสูงสุดบนขอบคม" (knife-edge) ที่พังทันทีถ้าค่าเพี้ยนไปเล็กน้อย โดยขยับทีละพารามิเตอร์ (ตัวอื่นคงที่ที่ค่า base) **ไม่ใช่การจูนหาค่าที่ดีกว่า** — จุดประสงค์คือดูความมั่นคง ไม่ใช่หาค่าที่ชนะ base

Base: `min_vol=1.17, min_wick=0.14, retest_depth=0.125, sl_mult=0.195` (ค่าเดียวกับที่ใช้ทดสอบ walk-forward)

## อ่านผล

**ไม่มีจุดขอบคม (knife-edge)** — ทุกพารามิเตอร์เปลี่ยนแบบ "ค่อยๆ ไหล" (smooth) ไม่มีจุดกระโดดหรือพังทันที:
- **min_vol** (กรองความถี่): ยิ่งเข้มขึ้น (สูงขึ้น) ไม้น้อยลงชัดเจน (6,362→2,389) แต่ PF ลดลงน้อยมาก (1.81→1.68) — แปลว่า filter ตัวนี้ไม่ใช่ตัวขับ edge หลัก แค่ตัวกรองปริมาณ
- **min_wick** (ความยาวไส้เทียนขั้นต่ำ): เข้มขึ้น (0.10→0.22) PF ลดลงตามเรื่อยๆ (1.79→1.67) ทิศทางสมเหตุสมผล (ไส้สั้นกรองได้สัญญาณคุณภาพต่ำกว่าปนมาบ้าง)
- **sl_mult** (ความกว้าง SL): กว้างขึ้น (0.15→0.25) PF ลดลงชัดสุดในกลุ่มนี้ (1.90→1.55) เพราะ SL กว้างขึ้น = risk ต่อไม้มากขึ้น แต่ TP คงที่ (tp_r×risk ขยับตามจริง แต่ MaxDD ต่อไม้จริงเพิ่ม) ทิศทางสมเหตุสมผล ไม่ใช่ความผันผวนสุ่ม
- **retest_depth** (ความลึกที่ย้อนเข้าไปตั้ง entry): ลึกขึ้น (0.08→0.18) PF ลดลงเรื่อยๆ (1.82→1.61) เพราะ entry ที่ลึกเกินไปมีโอกาสไม่ fill หรือ risk แคบเกินจนธรรมดากว่าจะคุ้ม

**ทุกทิศทางเปลี่ยนแปลงมีเหตุผลทางตรรกะรองรับชัดเจน** (Market Logic ตามข้อบังคับ #14) ไม่ใช่ตัวเลขสุ่มที่บังเอิญดีที่สุดแบบไม่มีคำอธิบาย

## สรุป

**ผ่านเกณฑ์ Rule #14** — ไม่พบสัญญาณ overfitting แบบ "จูนเฉพาะจุด" PF ยังคงเป็นบวกแข็งแรง (>1.5) ในทุกค่าที่ทดสอบรอบ base ±(15-80%) ของแต่ละพารามิเตอร์ รวมกับผล walk-forward และ rolling walk-forward ที่ผ่านมาก่อนหน้า ทำให้ S20.300 v2 เป็นดีไซน์แรกในเซสชันนี้ที่ผ่านการตรวจสอบ robustness ครบทั้ง 3 มุม (time-split, rolling, parameter sensitivity)

**ข้อสังเกตที่น่าสนใจ:** sl_mult=0.15 (SL แคบกว่า base) ให้ PF สูงสุด (1.90) — อาจบอกเป็นนัยว่า SL แคบลงอีกยังมีช่องให้ดีขึ้น แต่**ไม่ควรรีบเปลี่ยนไปใช้ค่านี้ทันที** เพราะนี่คือการสุ่มดูจุดเดียว ไม่ใช่การค้นหาอย่างเป็นระบบ (ต้องทำ grid search + walk-forward ซ้ำกับค่าใหม่ก่อน ไม่ใช่แค่เห็นเลขดีกว่าแล้วเปลี่ยนทันที — นั่นจะเป็นการทำ P-hacking ตามข้อบังคับ #14 เสียเอง)

## ข้อจำกัด

- ทดสอบทีละพารามิเตอร์ (univariate) ไม่ใช่ grid search หลายตัวพร้อมกัน (อาจมี interaction effect ที่ไม่เห็นในการทดสอบนี้)
- รันบนข้อมูลเต็ม 365 วัน ไม่ได้แยก IS/OOS ซ้ำสำหรับแต่ละค่าที่ขยับ (ถ้าจะเชื่อมั่นเต็มที่ควรทำ walk-forward ซ้ำกับทุกค่าที่ทดสอบ ไม่ใช่แค่ base)
- ยังไม่ทดสอบ tp_r และจำนวน stage ของ ratchet (คงที่ไว้ที่ค่า base ทั้งหมด)
