เข้าสู่โหมด "S20.14 Evolution (6 Patterns Optimization)" 
ภารกิจของคุณคือ: พัฒนา ค้นหา Filter หรือปรับจูนสมการพารามิเตอร์ใหม่ๆ ให้กับกลยุทธ์ย่อยทั้ง 6 ท่า (FVG, ATR, Fibo, Doji, Div, MA12) ของ S20.14 เพื่อลดสัญญาณหลอก (False Positives) และเพิ่มกำไรสูงสุด โดยมีกฎเหล็กดังนี้:

1. การตั้งชื่อและไฟล์:
   - ห้ามแก้ไขระบบบอทตัวหลักเด็ดขาด
   - ให้คัดลอกไฟล์ `export_patterns_csv.py` ไปสร้างเป็นเวอร์ชันใหม่ในโฟลเดอร์ `strategy/s20.14/backtest-sim/` เช่น `export_patterns_v1.py` (เริ่มที่ v1 และรันไปเรื่อยๆ)
   - ไฟล์เช็ค 35 ออเดอร์ให้ใช้ `check_35_orders.py` ตรวจสอบผลลัพธ์จากไฟล์ CSV (trades.csv) ที่เพิ่งสร้างใหม่เสมอ

2. วิธีการทดสอบ (Backtest):
   - รันสคริปต์ `export_patterns_v...py --days 365` (1 ปีเต็ม) เพื่อดึงและประมวลผลข้อมูลทั้ง 6 รูปแบบ 
   - รัน `check_35_orders.py` ทันทีเพื่อตรวจสอบว่าออเดอร์เป้าหมายยังอยู่ครบหรือไม่

3. เป้าหมายและเกณฑ์การผ่าน (Baseline ปัจจุบันบนระยะเวลา 365 วัน):
   - **เป้าหมายหลัก:** "ลดจำนวน Total Trades (ออเดอร์ขยะ/สัญญาณหลอก)" ลงให้มากที่สุด โดยที่ต้องรักษากำไร Net P&L ให้สูงขึ้นหรือเท่าเดิม
   - ⚠️ **กฎเหล็กสูงสุด (Sniper Rule):** เมื่อรัน `check_35_orders.py` จะต้องแสดงผลรวม "Match ครบ 35/35 ออเดอร์" (ไม่ว่าจะเป็น Time Match หรือ Exact Match) ห้ามหายไปแม้แต่ไม้เดียว! หากหายไปถือว่า "ล้มเหลวทันที"!
   
   **ตาราง Baseline รายท่า (ต้องทำให้ดีกว่าหรือเท่ากับค่าเหล่านี้):**
   - **ATR_D1**: Trades <= 953 | Win >= 454 | Loss <= 499 | WR >= 47.64% | P&L >= 40900.00
   - **ATR_H1**: Trades <= 12288 | Win >= 6425 | Loss <= 5863 | WR >= 52.29% | P&L >= 698700.00
   - **Div_H1**: Trades <= 7638 | Win >= 4230 | Loss <= 3408 | WR >= 55.38% | P&L >= 505200.00
   - **Doji_H1**: Trades <= 5931 | Win >= 3296 | Loss <= 2635 | WR >= 55.57% | P&L >= 395700.00
   - **Doji_M30**: Trades <= 1903 | Win >= 1024 | Loss <= 879 | WR >= 53.81% | P&L >= 116900.00
   - **FVG_D1**: Trades <= 5111 | Win >= 2876 | Loss <= 2235 | WR >= 56.27% | P&L >= 351700.00
   - **FVG_H1**: Trades <= 66771 | Win >= 36879 | Loss <= 29892 | WR >= 55.23% | P&L >= 4386600.00
   - **FVG_H12**: Trades <= 8250 | Win >= 4690 | Loss <= 3560 | WR >= 56.85% | P&L >= 582000.00
   - **FVG_M30**: Trades <= 21633 | Win >= 11978 | Loss <= 9655 | WR >= 55.37% | P&L >= 1430100.00
   - **Fibo_H1**: Trades <= 23134 | Win >= 12639 | Loss <= 10495 | WR >= 54.63% | P&L >= 1478300.00
   - **Fibo_M15**: Trades <= 15196 | Win >= 8349 | Loss <= 6847 | WR >= 54.94% | P&L >= 985100.00
   - **Fibo_M30**: Trades <= 7578 | Win >= 4176 | Loss <= 3402 | WR >= 55.11% | P&L >= 495000.00
   - **MA12_H1**: Trades <= 18549 | Win >= 10713 | Loss <= 7836 | WR >= 57.76% | P&L >= 1359000.00
   - 🚫 **กฎห้ามโกง (Anti-Cheat):**
     1. **ห้าม Hardcode วันเวลา:** ต้องใช้ตรรกะ Price Action/Indicator/Math เท่านั้น
     2. **ห้าม Look-Ahead Bias:** ห้ามดึงข้อมูลแท่งเทียนในอนาคต (การเช็ค SL/TP ต้องใช้ลูปเดินหน้าทีละแท่งแบบ Walk-Forward เสมอเหมือนที่ทำอยู่)

4. วิธีการทำงานของคุณ (ทำวนลูปไปเรื่อยๆ):
   - เสนอไอเดียปรับจูนพารามิเตอร์สำหรับ "ทีละ 1 ท่า" (เช่น ปรับ Fibo Lookback, เพิ่ม RSI filter ให้ FVG, แก้เงื่อนไขขนาดไส้ของ Doji ให้รัดกุมขึ้น)
   - สร้างไฟล์เวอร์ชันใหม่ (เช่น v1) และปรับแก้โค้ดเฉพาะจุดนั้น
   - สั่งรัน Backtest 365 วัน ตามด้วย `check_35_orders.py` ทันที 
   - ถ้าออเดอร์ 35 ไม้หลุดหายไป (แม้แต่ไม้เดียว): ให้สรุปสั้นๆ ว่าล้มเหลวเพราะตัวกรองตึงเกินไป แล้วขยับไปสร้างเวอร์ชันถัดไป (v2) พร้อมไอเดียใหม่ หรือคลายพารามิเตอร์ออก
   - ถ้า 35 ไม้ยังอยู่ครบ และจำนวน Trades ลดลง/กำไร P&L รวมของท่าย่อยนั้นเพิ่มขึ้น: ให้รายงานสรุปผลให้ฉันทราบ โดยแยกสถิติตามท่า (Trades, Win, Loss, WinRate, P&L) และยืนยันว่า 35 ไม้ยังอยู่ครบ ก่อนที่จะเริ่มปรับปรุงท่าอื่นต่อไป
